# Reference reconciliation

## Route and legacy evidence

The canonical route reference and both supplied legacy route sets agree on 116 routes: one home, 15 sector/category hubs, and 100 guides. The legacy Next archive is an App Router/TypeScript renderer with contracts, seed registry, and components; its build report says dependency installation timed out, so it did not verify a dependency-backed Next production build. The static variation uses a dependency-free Node generator and contains an existing generated `dist/`, but its notes do not establish a current independent production verification. The archive README also warns that ZIPs need a separate public-repository safety review.

Both variations' route/content contracts were inspected alongside the extracted Next seed registry, the static project's package/build contract, and the supplied legacy reference notes. The legacy pages are evidence, not current operational truth.

## Reused from Funding and Solutions

- Funding's Barlow Condensed / DM Sans typography, cream paper, near-black structure, orange/blue/lime accents, hard borders, restrained offset shadows, skip link, and responsive neo-brutalist shell.
- Funding's static App Router rendering, reusable page templates, route audit convention, and clear product ownership boundaries.
- Solutions' typed Zod contracts, central metadata and JSON-LD helpers, explicit noindex gate, concise generated manifests, client-only interactive diagnostics, and review-status fields.
- Solutions' compact sector/outcome navigation and mobile disclosure behavior were adapted for four curated sector clusters.

## Improved or distinct

- The home route is an Industry Finder using the full 100-guide catalog, sector filtering, search, recovery state, and canonical result routes.
- Sector hubs map qualitative cash-cycle steps, cost centers, operation prompts, all child guides, FAQs, and verified handoffs.
- Each guide uses retained operator-specific units and a unique legacy seed pressure point, with its own related preparation questions, costs, uses, and visible FAQs. Local diagnostics explain their inputs and do not score eligibility or send data.
- Sector-sensitive adaptations preserve payer/claim timing in healthcare, platform settlement and returns in ecommerce, property-level cash flows in real estate, and restricted-fund distinctions in education/nonprofits.
- A deterministic date-range explorer demonstrates the difference between a paid cost date and expected receipt date without projecting finances.
- Noindex is unconditional; the sitemap is empty, and no custom domain or external endpoint is configured.

## Discarded and deferred

- The legacy “Variation 3” CSS and trading-terminal framing were not copied. Funding/Solutions are the visual precedents.
- The legacy application URL, provider/product-like paths, approval/underwriting signals, hard-coded document requirements, stale metadata, and any unsupported numeric claims were removed or not imported.
- Acquire, Tools, Wix publication paths, analytics, and lead intake are not activated because current destinations were not verified for this property and those systems remain owned elsewhere.
- The supplied references disagree in confidence: the old static output exists but has not been independently rebuilt in this task, while the old Next report expressly lacked a production build. Neither report is used as evidence that this new app builds.

## Material content note

Guide-specific operator units and first pressure-point statements come from the extracted legacy seed registry. Other field-guide sections are editorial adaptations based on that context. All content is marked for review; no page receives a fabricated review date or indexing approval.
